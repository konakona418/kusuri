# Kusuri 开发计划(v1)

> 定稿:2026-09-28 · 状态:已确认
> Kusuri(薬)是一个个人用药提醒与记录 Android 应用。自用为主,按可发布标准开发。

## 1. 产品原则

- **自用为主,按可发布标准做**:权限走正规申请与降级流程;无遥测;文案全部资源化(默认中文,英文后补);签名与版本管理预留发布空间。
- **无遥测,数据只在本机**:App 功能不依赖互联网,也不含任何主动外联代码。`INTERNET` 权限仅用于你手动开启的局域网导出(直连你自己的电脑,无服务器),权限用途与代码位置见 `docs/lan-export.md` §9。
- **数据可携带**:保留 Android 系统自动备份;提供手动导出与导入。
- **提醒可靠优先于功能多**:提醒不响是最严重的缺陷,一切设计为"失败可见"服务。

## 2. 范围

### v1 包含

- 四种调度模式 + 餐时标签:每天固定时间、间隔制(每 N 小时/天,固定锚点)、按需(PRN)、疗程边界
- 通知提醒(单次提醒 + 通知动作)与可靠性向导
- 服药记录(打卡、补记、跳过、错过派生)与打卡时双 offset 展示
- 库存计数与低库存补药提醒
- 历史时间线与近 7/30 天遵守率
- CSV / JSON 导出与导入:JSON 为完整备份/恢复(换机),CSV 为服药记录导出(按时间区间,给医生看)

### v1 明确不做

递减剂量(taper)、每周固定几天、云同步、统计图表、全屏闹钟、重复响铃、多用户、自动盘点流程。

## 3. 领域模型

| 实体 | 字段(草案) | 说明 |
|---|---|---|
| `Medication` | 名称、剂型单位(粒/ml 等)、默认剂量、餐时标签(饭前/饭后/随餐/无)、备注、创建时间、归档状态 | 用户录入的药物本体 |
| `Schedule` | 模式枚举 + 模式参数 | 每条药一个排程 |
| `Course` | 开始日期、结束日期(可空) | 长期药无结束日期 |
| `Stock` | 当前数量、低库存阈值(默认 5)、告警已武装标志 | 数量由事件与记录派生见 §6 |
| `StockEvent` | 补货 / 调整、增减量、时间 | 手动维护 |
| `DoseRecord` | 药物、计划时间(PRN 可空)、实际时间、数量、动作(TAKEN/SKIPPED)、来源(应用内/通知/补记) | 记录是唯一事实源 |

### 计划剂量的派生规则

"计划剂量"不是表实体,而是由排程 + 日期范围 + 时区**展开**的派生概念;"错过"同样派生,避免后台改状态带来的并发与一致性问题:

- 无记录且 `now < 计划时间` → **待处理**
- 无记录且 `计划时间 ≤ now < 计划时间 + 宽限窗口` → **待处理(逾期)**
- 无记录且 `now ≥ 计划时间 + 宽限窗口` → **错过**(可改为补记)
- 有 `TAKEN` 记录 → **已服用**(显示实际时间;与计划有偏差时附"早/晚 X")
- 有 `SKIPPED` 记录 → **跳过**

宽限窗口:全局默认 2 小时,设置页可改;v1 不做每条药覆盖。

### 调度模式定义

1. **每天固定时间**:一天 1~N 个时间点。
2. **间隔制**:固定锚点循环,不按实际服药滚动。
   - 每 N 小时:锚点时刻起按**绝对时长**循环(如每 8 小时 @ 8:00 → 8:00 / 16:00 / 24:00)。间隔语义优先,跨夏令时保持真实间隔。
   - 每 N 天:锚点日期 + 时间,如每 2 天 @ 9/1 8:00 → 9/1、9/3、9/5…(同一本地钟点)。
   - 打卡时展示两个 offset(见 §4.3);不重排后续锚点。
3. **按需(PRN)**:不排程、不主动提醒。记录时校验可配置的"最少间隔"与"每日上限"(均可空),超限以黄/红警告提示,但不阻止记录(记录 = 事实)。
4. **疗程边界**:开始日期(默认创建日)与可选结束日期(含当天)。到期后自动停止提醒、标记"已完成"归档(记录保留);可一键延长(修改结束日期)。

## 4. 提醒与记录语义

### 4.1 提醒投递

- 到点发送通知:**单次**;走**普通通知**(非闹钟式,不使用 alarm 类别/全屏)。提醒等级**两档**——静默(`IMPORTANCE_LOW`,无声无震,只在通知栏)/ 横幅(`IMPORTANCE_HIGH`,响铃 + 震动 + 顶部弹出)。渠道的重要性创建后应用改不了(平台约束),所以一档一条渠道,发送时按设置选一条;设置里可当场「试一下」当前档位。**全局只有一个等级**:服药提醒、通用提醒(§14)、低库存补药提醒都按它选渠道,不再按类型分档。**中间档刻意不做**:参考文档里"重要性至少 DEFAULT 才应该有声音",把"只震动"塞进 LOW 与平台模型打架,各家系统 UI 处理还不一致;而 DEFAULT 与 HIGH 在多数系统 UI 里又被折叠成同一档。无重复响铃(v2 候选)。
- 通知动作:`[已服用]` `[稍后 15 分]` `[跳过]`;动作通过 BroadcastReceiver 直接落库,不打开 app。
- **同一计划时刻的多味药折叠成一组**:组摘要列出药名(收起时只看这一行),展开后每味药各自带着自己的三个动作;组内**只响一次**(声音交给摘要 `GROUP_ALERT_SUMMARY` + `FLAG_ONLY_ALERT_ONCE`),到点重建时只剩一味药会自动退回单独一条。**记录之后只做减法,一次 `notify` 都不发**:只撤掉已处理的(组里剩不到两味时连摘要一起撤掉),其余一概不碰——重挂是"把这一刻别的药再弹出来",而"更新摘要的数字"同样是重挂:实测小米 HyperOS 对任何 `notify` 都会重新上屏(`AlertCoordinator` 的 `onViewBound`)。代价是摘要上的味数会暂时偏大,直到下一次到点/开机重建时校正;数字从来不是重点(§11)。
- 稍后:固定 15 分钟,可反复;**不暂停错过计时**(记录遵循事实)。
- 通知保留至用户处理;未处理的通知在次日凌晨由通知自身到期自动撤下(避免过期通知误导)。宽限到期判"错过"不会撤下通知,错过状态只在 App 内呈现。
- 通知渠道单条"用药提醒";文案模板:`药名 剂量` / `计划时间 · 餐时标签`。

### 4.2 权限与降级

- `POST_NOTIFICATIONS`:Android 13+ 运行时申请。
- `SCHEDULE_EXACT_ALARM`:Android 12+ 走设置跳转引导;**不使用** Play 政策受限的 `USE_EXACT_ALARM` 与全屏 intent;权限被拒时降级为窗口/非精确闹钟并在状态灯中明确告知。
- `RECEIVE_BOOT_COMPLETED`:manifest 声明,用于开机重排。
- 电池优化:仅跳系统设置页手动加入白名单;**不申请** `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`(Play 限制)。

### 4.3 打卡时的双 offset

记录一个计划剂量时展示:

1. **与计划的偏差**:`比计划晚 1 小时 05 分`
2. **距上次实际服药的间隔**:`距上次服药 6 小时 20 分(医嘱间隔 8 小时)`

对 PRN,只有第 2 项;医嘱间隔来自间隔制配置或 PRN 的最少间隔。

### 4.4 剂量

每条药设默认剂量;固定药一键按默认记录;PRN 记录时可改数量(快捷 1/2/自定义)。

## 5. 可靠性

- **可靠性向导**(首次启动,可跳过、可重进):①通知权限 → ②精确闹钟权限 → ③电池优化白名单。
- **提醒健康检查**(设置页):状态灯展示各环节是否健康,并给出一键修复入口。
- 排程策略:每条药维护"下一个未完成剂量"的精确闹钟;触发后重排该药下一次;`BOOT_COMPLETED` / `TIME_SET` / `TIMEZONE_CHANGED` / 应用更新后全量重排,并顺手把这段时间里本该响过、还真没响的补上。**不做自建的定时巡检**:WorkManager 与闹钟受同一套省电策略约束,系统按住闹钟时也按住巡检(兜不住),能按时跑的时候又只是每小时把已经到点的旧通知重挂一遍(纯打扰)。
- **补发(失败可见的兜底)**:只在**平台叫我们**的时刻做——开机 / 改时间 / 改时区 / 应用更新,以及闹钟响了却认不出目标(有的 ROM 会把后台广播的 extras 剥空)。这时把今天"**已经到点、仍在宽限窗口内**"的剂量、以及最近一小时内本该响过的提醒重新挂上通知:手机是真关机了、闹钟是真没响,补发才不是打扰。幂等——已经挂着的只做原地更新,不会重复响;已经处理过的不出现。打开 App 不补发:人就在 App 里,今天页写着"到时间了"、历史页写着"错过"。
- 诚实原则:降级/失效必须可见,不静默。

## 6. 库存

- 初始数量录入;每次 `TAKEN`(含补记)按实际数量扣减;跳过/错过不扣。
- 补货/调整以 `StockEvent` 记录(`+N` / 校准)。
- 低库存:剩余数量 ≤ 阈值(默认 5,可调)且告警处于武装状态 → 提醒**一次**;补货后重新武装,下次跌破再提醒。
- 武装规则:新建药物时只有录入了库存(剩余 > 0)才武装;从未录入库存的药物不打扰,补货后进入正常告警周期。
- 检查时机:每次记录写入后、补货/调整后、app 启动与开机重排时。

## 7. 界面(五标签 + 设置入口)

- **今日**(主页):当天时间线(时间、药名、剂量、标签、状态、操作);今天到期的**通用提醒**区块;PRN 快速记录区(显示距上次间隔与今日次数);库存告警横幅。待处理项提供 `[已服用]` `[跳过]`;错过项提供 `[补记]`。排序:**待处理**的在前(未到点 + 到点但仍在宽限窗口内),已服用/跳过/错过/未追踪的在后,两组内都按计划时间由早到晚——刚到点的那一剂留在最上面。
- **提醒**:通用提醒(复诊/取药/复查/日常事项)的分组列表:即将到来 / 已过期 / 已完成;FAB 新建,点一条改,长按删除。见 §14。
- **药物**:活跃列表(下次提醒、剩余数量、疗程进度);归档项折叠;FAB 新增。详情页含基本信息、排程、疗程、库存(补货/调整)、该药记录、延长/归档/删除。
- **历史**:近 7/30 天遵守率卡片 + 按天分组时间线;可修改/补记/撤销历史记录。顶部一行**筛选**——时间范围(今天 / 近 7 天 / 近 30 天 / 自定义起止)+ 弹窗里的类型(服药 / 症状 / 随手记)、药物、状态(已服用 / 已跳过 / 已错过 / 未处理,只作用于服药行);筛选**只作用于时间线**,遵守率卡片恒为近 7 / 30 天(全量结论),筛选状态不落盘、重启回默认。**同一计划时刻的多味药折叠成一行**(右侧带展开箭头,默认折起;折叠行只显示组内**最需要注意的一个状态词**——已错过 > 到时间了 > 待服用 > 已跳过 > 未追踪 > 已服用,不显示数量),点开成一行一味。点开某一条时,动作按 `doseStatus(now, 宽限窗口)` 给:未到点/到点未处理 → 已服用 / 跳过;已超时 → 补记(也能选跳过);已有记录 → 改时间/改动作 + **长按取消服用**。归档项的记录仍显示。
- **设置**(顶栏齿轮):提醒等级、提醒健康检查、宽限窗口时长、导出/导入、局域网导出(扫码)、关于。

## 8. 技术方案

- 单 `:app` 模块;Kotlin 2.2.10 + Compose(Material3)+ Navigation Compose;ViewModel + StateFlow;手动 DI(`AppContainer`,不引 Hilt)。
- **Room** 存储;调度引擎为**纯 Kotlin** 领域代码并注入 `Clock`,与 Android 框架解耦以便单测。
- **AlarmManager** 精确闹钟排程(补发也只在平台事件上做,不引 WorkManager);`java.time` + core library desugaring(minSdk 24)。
- 导出:CSV(人读,给医生看,按时间区间)+ JSON(全量备份/恢复,含 schema 版本号);通过 SAF 读写,无需网络。另有**局域网导出**(扫码推送到自己电脑上的接收脚本),见 §13 与 `docs/lan-export.md`。
- 时间语义:展示与排程均用设备本地墙钟时间;记录存绝对时间(epoch)。固定时间与锚点随当地时区(DST 用 `ZonedDateTime` 处理)。
- 备份:保持 `allowBackup` 与现有 `dataExtractionRules`。
- 测试:调度引擎单测(DST、时区切换、跨天、宽限边界、锚点展开)、DAO 测试、关键流程 UI 冒烟;真机提醒验收清单(锁屏过夜)。

## 10. 风险与平台陷阱

- **OEM 电池管理**(小米/华为等)杀后台 → 向导 + 状态灯缓解;交付前在真机做"锁屏过夜提醒"验收。
- 精确闹钟权限被拒 → 提醒可能延迟;状态灯明示,文案诚实。
- Android 14+ 用户仍可滑掉常驻通知;Android 13+ 需通知权限 → 可靠性不依赖通知"锁死"。
- Doze 对 `setExactAndAllowWhileIdle` 有频率限制 → 本应用提醒密度低,安全。
- `targetSdk 37` 的新行为变化 → 每个里程碑真机验证。

## 12. M6:日志(症状与随手记)

> v1 五个里程碑之外的增量能力。范围已确认,按 M6.x 渐进交付。

### 范围

- 两类条目,同一条时间线:
  - **症状**:内置常见标签 + 自定义;严重程度 **1–5**;备注选填;**可选**关联某味药(默认不关联)
  - **随手记**:自由文本 + 时间
- 入口:底部导航新增第 4 个标签「**记录**」(今日 / 记录 / 药物 / 历史)
- 「记录」页:按天倒序的条目列表 + 新建入口
- **并入历史时间线**:与服药记录按天并列,图标/底色区分
- 趋势:点某个症状 → 近 30 天的 1–5 变化(点/折线)
- 条目可改、可删
- 备份/导出:JSON 备份格式升到 **v2** 纳入日志(仍兼容导入 v1 备份);CSV(给医生)增加症状信息

### 明确不做

- 数值指标(血压/血糖/体温等)
- "提醒我记录"的定时通知
- 多症状叠加图表、周/月切换图表页

### 数据

- 新表 `log_entries`:`id`、`type`(SYMPTOM | NOTE)、`at`(epoch millis)、`symptom`、`severity`、`medicationId`、`note`
- **删除药物时日志保留**:外键 `ON DELETE SET NULL`(日志是"我的身体记录",不应随药物消失);这与服药记录的级联删除不同,是有意为之
- Room 版本 **2 → 3**,带正式迁移(建表 + 索引)
- 症状标签:内置建议 + "最近使用"记忆,不单独建表;条目存文本

### 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M6.1 数据与领域 | `log_entries` 表 + 迁移、领域模型、仓库 + 测试 | 能读写症状与随手记 |
| M6.2 记录页 | 「记录」标签、列表、新建/编辑/删除(含程度与可选关联) | 能录入并修改真实症状 |
| M6.3 并入历史 | 历史时间线并列显示日志条目 | 同一天的服药与症状一眼对上 |
| M6.4 趋势 | 单症状近 30 天变化 | 能看到某个症状在好转还是加重 |
| M6.5 备份导出 | JSON v2 备份/恢复、CSV 含症状 | 换机恢复含日志;CSV 可给医生 |

## 13. M7:局域网导出(扫码推到电脑)

> 契约全文见 [`docs/lan-export.md`](lan-export.md);本节只记范围与验收。

### 范围

- 电脑端接收脚本 `tools/kusuri-receive.py`(`uv` + PEP 723 内联依赖,标准库 + `segno`):打印地址 + 会话口令 + 二维码;`POST /upload` 校验口令、原子落盘、回显路径与 `sha256`。
- 手机端:设置 →「备份与导出」→「局域网导出(扫码)」独立路由页,四状态(扫码中 / 已识别目标 / 发送中 / 成功或失败)。
- 目标输入:扫码为主,手输兜底——完整式 `192.168.2.110:47821#K4F9M2` 与"用手机本机 `/24` 补全"的短式 `110#K4F9M2` 共用同一解析器。
- 发送内容:JSON 全量备份 + CSV 服药记录(复用现有区间选择对话框),字节与 SAF 导出一致(同一个 `BackupService`)。
- 权限:`INTERNET`、`CAMERA`(运行时申请,被拒后走手输);`<uses-feature android:name="android.hardware.camera" android:required="false" />`。
- 传输:裸 socket 手写这一个 POST(理由见契约 §6);不做 HTTPS、不做反向导入。

### 明确不做

反向导入(电脑 → 手机)、mDNS/DNS-SD 发现、UDP 广播探测、HTTPS/自签证书、公网中转、IPv6、多台电脑同时接收。

### 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M7.1 契约与电脑端 | `docs/lan-export.md` 定稿、`tools/kusuri-receive.py` | 手起脚本,`curl` 发送落盘;错口令 `401` 且不落盘;`../` 文件名被剥成 basename |
| M7.2 手机端逻辑 | `LanExportTarget` 解析(完整式 / 短式 / 边界)、`LanExportClient`(裸 socket 请求 + 应答与错误映射) | 单测:JVM 里起本地 `ServerSocket` 对打,验请求字节、`sha256` 比对、错误映射 |
| M7.3 手机端页面 | 路由页、四状态、手输入口;把 `CsvRange` / `CsvRangeDialog` / `CsvLabels` 从设置页提取为共享件 | 真机用手输路径发 JSON 与 CSV 均成功 |
| M7.4 扫码 | CameraX 取景器 + zxing 解码 + 自绘取景框 + 相机权限降级 | 真机扫码识别、闪绿 + 短震动、权限被拒时手输可用 |
| M7.5 收尾 | 声明与文案(README / `plan.md` / `strings.xml`)、README「权限说明」、`docs/release.md` 发布检查清单(现有"不含 `INTERNET` 权限"一条必须改为权限清单核对)、release 冒烟 | 口径一致;R8 release 包两条路都通 |

### 验收(整体)

电脑上落盘的文件**能被手机 SAF 导入回去,且药物数与记录数一致**;错口令 → `401` 且不落盘;不启脚本 → 明确提示;相机权限被拒 → 手输兜底可用;两端 `sha256` 一致;R8 release 包两条路都通。

### 风险

- 终端二维码可能因行距/字体扫不出来 → 备选 `--png` 另存 PNG。
- `camera-compose` 的 `CameraXViewfinder` 要手动喂 `SurfaceRequest` → 组合别扭就退到 `AndroidView(PreviewView)` + `LifecycleCameraController`(文档路径)。
- 访客网 / AP 客户端隔离会让直连失败 → 提示文案要能指到这一步。
- APK 体积预估 +1.5~2 MB(相机栈)。
- 明文 HTTP 的保密性依赖网络本身 → 文档明示,推荐"手机开热点、电脑连热点"的用法。

## 14. M8:通用提醒(复诊 / 取药 / 复查 / 日常事项)

> v1 与 M6/M7 之外的增量能力。范围已确认,按 M8.x 交付。

### 范围

- 一条提醒 = 标题 + 第一次的时刻(精确到分)+ 重复规则 + 选填备注。
- 重复规则:**不重复 / 每天 / 每周 / 每月 / 每 N 天 / 每 N 月**。
- **只存第一次的时刻 + 规则**,之后每一次都由规则算出来(与服药排程同一套"派生而非展开"的思路):
  - 重复保持**本地钟点**,夏令时按墙钟走;
  - 月类规则锚定第一次那天的日号,短月回退到月末且**不漂移**(1/31 → 2/28 → 3/31,不是 3/28)。
- 通知:到点发一条,动作 `[知道了]` `[稍后 15 分钟]`;备注在展开态里。渠道与等级与其余通知共用(§4.1)。
- 解释语义:**只有一次性提醒有"完成"**("知道了"落 `doneAt`);重复提醒的"知道了"只收掉这次通知,下一次照旧。
- 列表:第 5 个标签「提醒」,分 **即将到来 / 已过期 / 已完成**;到期未处理的一次性提醒显示"已过期",可 `[标记完成]`;点一条改,长按删除。今日页顶部同时显示今天到期的提醒,点一下跳到提醒标签。
- 归档与编辑:改一条已完成的提醒等于让它重新生效(`doneAt` 清空)。
- 备份:JSON 升到 **v3** 纳入提醒(v1/v2 仍可导入);清库一并清空。CSV 不含提醒——它是给医生看的服药记录,不是日程。
- 数据:新表 `reminders`;Room **3 → 4** 带迁移。

### 明确不做

- **提前提醒**(如"复诊前一天再响一次"):v1 只在设定时刻响一次。
- 与药物 / 库存联动(取药自动关联某味药)、按周几多选的重复、节假日例外日。
- 每次发生的完成历史(只记"已完成 / 未完成",不记每一次的流水)。

### 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M8.1 数据与领域 | `reminders` 表 + 迁移、`ReminderSchedule`(下一次 / 当天有没有)+ 单测 | 月类不漂移、短月回退、本地钟点跨夏令时 |
| M8.2 通知闭环 | `ReminderChannels` 统一渠道、`ReminderNotifier`、到点闹钟与重排、通知动作 | 真机定时收到;知道了 / 稍后都正确落地 |
| M8.3 提醒页 | 第 5 个标签、分组列表、新建 / 编辑 / 删除、今日页区块 | 能录入并管理真实提醒(复诊、复查) |
| M8.4 备份收尾 | JSON v3、清库、文案与文档 | 换机恢复含提醒;旧备份仍可导入 |

## 11. 决策记录

| 决策点 | 结论 | 关键理由 |
|---|---|---|
| 定位 | 自用为主,按可发布标准 | 功能可靠优先,同时不欠发行债 |
| 网络 | 无遥测;`INTERNET` 仅用于手动开启的局域网导出(直连你自己的电脑,无服务器) | 保留可审计性:权限用途与代码位置写清,而不是笼统声明"零权限" |
| 局域网导出 | 电脑当主机、手机扫码(或手输)推送 | 手机不监听端口,不暴露健康数据端点;落盘与文件命名由电脑端负责 |
| 扫码 | CameraX + zxing(不引 Google 服务) | 全离线、可审计;代价是 APK 增大约 1.5–2 MB |
| 备份 | 系统自动备份 + CSV/JSON 手动导出导入 | 丢手机不丢记录,数据可携带 |
| 调度内核 | 固定时间 / 间隔固定锚点 / PRN / 疗程 + 餐时标签 | 覆盖真实需求,放弃 taper 与周几 |
| 间隔基准 | 固定锚点;不随实际服药滚动 | 提醒可预测,偏差在打卡时呈现 |
| 餐时 | 纯标签,不建餐时模型 | 简化调度,够用 |
| 错过 | 计划 + 宽限(默认 2h)派生,可补记 | "记录=事实",误判可纠正 |
| 稍后 | 有按钮,不暂停错过计时 | 保持记录原则 |
| 提醒强度 | 单次提醒 + 尽量常驻,无全屏/重复响铃;等级只有静默 / 横幅两档,一档一条渠道 | 克制的打扰;渠道重要性创建后不可改,中间档与平台模型打架(把"只震动"塞进 LOW),MIN/NONE 更是静默失败 |
| 通知折叠 | 同一计划时刻靠系统通知分组折叠,组内只响一次,逐条动作保留 | 与历史列表同一心智模型(收起看名字、展开各自处理);折叠的意义是减打扰,不是只省版面 |
| 记录后不重挂 | 记录一味药之后只撤不挂:不改摘要、不动卡片 | 重挂(含"只是把摘要数字改小")都会被系统重新上屏——小米 HyperOS 实测对任何 `notify` 都 `buzzBeep`;吃一味药不该让别的药再弹出来。味数会滞后到下一次到点/开机重建,而数字不是重点 |
| 不做定时巡检 | 补发只在平台叫我们时做(开机 / 改时间 / 时区 / 应用更新、闹钟认不出目标) | WorkManager 与闹钟受同一套省电策略约束,系统按住闹钟时也按住巡检——换来的不是可靠性,是可靠的错觉;能按时跑时又只是重复打扰 |
| 剂量 | 默认剂量 + 可改数量 | 库存与安全上限的准确来源 |
| PRN | 可配最少间隔 / 每日上限 | 防止短时间重复用药 |
| 库存 | 简单计数 + 数量阈值提醒 + 手动补货 | 克制版库存,不做自动盘点 |
| 统计 | 时间线 + 近 7/30 天遵守率 | 唯一真正有用的心智数字 |
| 历史筛选 | 时间范围 / 类型 / 药物 / 状态四维,只作用于时间线 | 遵守率是全量结论,不该跟着筛选变;四维各自独立,组合可预期 |
| 历史折叠行 | 只显示一个状态词,取组内最需要注意的状态 | 数量词不说明任何事,漏服又必须看得见 |
| 信息架构 | 五标签(今日/记录/提醒/药物/历史)+ 设置入口 | 主页即"今天要吃什么";提醒是"将要发生的事",与记录(已发生)分开摆 |
| 通知配置 | 一个全局「提醒等级」(静默/横幅)管所有通知:服药、通用提醒、低库存共用两条渠道 | 只有一个开关,行为可预期;渠道重要性创建后不可改,所以一档一条渠道 |
| 通用提醒 | 独立实体,只存首次时刻 + 重复规则(不重复/每天/每周/每月/每 N 天/月),不设提前提醒 | 派生而非展开;复诊(一次性)、复查(定期)、日常(每天/每周)都能表达 |
| 提醒的完成 | 只有一次性提醒有"完成",重复提醒只记规则 | 重复提醒不该被一次"知道了"永久停掉 |
| 可靠性 | 完整向导 + 健康检查状态灯 | 把静默失败变成用户知情 |
| 节奏 | 里程碑渐进交付 | M2 结束即可日常使用 |
