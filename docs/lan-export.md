# 局域网导出(扫码推送到电脑)

> 状态:契约已定稿(2026-09-28)· 属于 **M7** · 读代码前先读 §7「安全边界」

手机上的 JSON / CSV 导出,除了 SAF(存到手机或网盘),还可以在**你手动开启**时直连你自己的电脑推过去。

拓扑刻意是**电脑当主机、手机当客户端**:

- 手机**不监听任何端口**,不会把健康数据端点暴露在局域网上。
- 电脑上跑一个接收脚本,它就是"主机":打印地址 + 口令 + 二维码;手机扫码 → 确认目标 → 推送 → 电脑落盘并回显路径。
- 全程局域网直连。**没有中转服务器,没有遥测,数据不出局域网。**

## 1. 前置条件

| 条件 | 说明 |
|---|---|
| 同一局域网 | 家庭 Wi-Fi;或手机开热点、电脑连手机热点(最严谨的用法,见 §7) |
| 同一子网 | 短式手输(§4.2)依赖这一点;不同子网时用完整式 |
| 电脑 | Python 3.11+,`uv` 在 PATH 里 |
| 手机 | Android 应用本身;相机权限(仅扫码时需要,可拒绝后用 §4.2 手输) |

## 2. 电脑端:接收脚本

```bash
uv run tools/kusuri-receive.py                 # 默认端口 47821,默认落盘 ~/Downloads
uv run tools/kusuri-receive.py --out ~/Documents/kusuri
```

脚本用 PEP 723 内联依赖,`uv run` 会自己建环境,不需要提前 pip install。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | `47821` | 被占用时依次尝试 47822…47830,并打印实际端口 |
| `--out` | `~/Downloads` | 落盘目录 |
| `--code` | 随机 | 固定会话口令(手写 `curl` 测试时有用) |
| `--no-qr` | 关 | 不打印二维码 |
| `--png <路径>` | 关 | 另存一张二维码 PNG(终端二维码偶尔真的扫不出来) |
| `--idle-timeout <秒>` | `0`(关闭) | 空闲超时后自动退出;默认纯常驻 |
| `--bind` | `0.0.0.0` | 绑定地址 |

行为:

- **纯常驻**:一直服务到你 `Ctrl-C`。每次成功接收都打印保存路径、字节数与 `sha256`。
- 地址选择:用"连一个 UDP 假地址(`192.0.2.1`,不会真的发包)看内核选了哪张网卡"的办法拿到**出口网卡**的 IPv4,因此不会把 `docker0` / `virbr0` 之类的地址打出来;有多张候选时全部列出。
- 终端二维码在 stdout 是终端时用显式**深色码点 + 浅色底**,不受终端配色主题影响(反色二维码部分扫码器识别不了);输出被重定向时则是普通字符画。

## 3. 协议契约

两端唯一的接口。

### 3.1 请求

```
POST /upload HTTP/1.1
Host: 192.168.2.110:47821
X-Kusuri-Code: K4F9M2
X-Kusuri-Kind: json | records
X-Kusuri-Filename: kusuri-backup-2026-09-28T1432.json
Content-Type: application/json; charset=utf-8      # 或 text/csv; charset=utf-8
Content-Length: 12345
Connection: close

<导出文件的原始字节>
```

| 头 | 必填 | 说明 |
|---|---|---|
| `X-Kusuri-Code` | 是 | 会话口令,六位 Crockford base32 |
| `X-Kusuri-Kind` | 是 | `json`(全量备份)/ `records`(CSV 服药记录) |
| `X-Kusuri-Filename` | 是 | 建议文件名;脚本只取 basename,拒绝路径分隔符,截断到 120 字符 |

- 请求体**就是导出的文件字节**,逐字节落盘。手机侧复用 `BackupService.exportJson()` / `exportCsv()`,不存在第二套序列化。
- 不收 `Transfer-Encoding: chunked`;`Content-Length` 必填。
- 大小上限 32 MB,超限直接 `413` 且不写盘。

### 3.2 应答

| 状态 | 体 | 何时 |
|---|---|---|
| `200` | `{"ok":true,"saved":"/home/lain/Downloads/kusuri-backup-….json","sha256":"…","bytes":12345}` | 成功落盘 |
| `400` | `{"ok":false,"error":"bad_request"}` | 缺头、方法不对的 `/upload`、`chunked` |
| `401` | `{"ok":false,"error":"bad_code"}` | 口令不匹配(每次失败 `sleep(0.5)` 限速) |
| `404` | `{"ok":false,"error":"not_found"}` | 其它路径 |
| `405` | `{"ok":false,"error":"method_not_allowed"}` | 其它方法 |
| `413` | `{"ok":false,"error":"too_large"}` | 超过 32 MB |
| `422` | `{"ok":false,"error":"bad_payload"}` | `kind: json` 但体不是合法 JSON,或体为空 |

- 落盘**原子化**:先写 `<最终名>.part`,成功后 `os.replace` 改名。发送中途被打断不会留下半个文件。
- **重名不覆盖**:已存在时自动追加 `-1`、`-2`。
- `GET /` 返回一个给人看的存活页(已接收数量与最近接收时间),方便用浏览器确认"脚本还活着"。**刻意不显示口令与文件名**:这个页面局域网内任何人都能访问,口令只出现在运行脚本的终端里。
- 完整性:**手机算出发送字节的 `sha256`,与应答里的 `sha256` 比对**,一致才显示"校验一致"。

### 3.3 超时

连接 5 s、读 15 s、`Connection: close`。任一端超时都不静默重试(重试可能造成重复文件)。

## 4. 手机端怎么知道往哪发

### 4.1 扫码(主路径)

二维码内容:

```
kusuri://lan-export/1?h=192.168.2.110&p=47821&c=K4F9M2
```

| 字段 | 含义 |
|---|---|
| `lan-export/1` | 用途 + 版本号,便于以后改协议时拒绝老码 |
| `h` | 主机 IPv4 字面量(接受主机名留给以后) |
| `p` | 端口 |
| `c` | 会话口令 |

用自定义 scheme 而不是 `http://`,是因为:别的扫码 App 扫到不会当网址打开,手机端也不会把口令写进浏览器历史。

### 4.2 手输(兜底,与扫码共用同一个解析器)

| 形式 | 例子 | 说明 |
|---|---|---|
| 完整式 | `192.168.2.110:47821#K4F9M2` | 任何时候都能用(端口可省略,默认 47821) |
| **短式** | `110#K4F9M2` | 用**手机自己所在网段的 `/24` 前缀**补全;脚本会把这一行一起打印出来 |

短式成立的前提是两端同子网——而这本来就是整个功能的前提;手机拿不到自己的 IPv4 时,短式报错并提示用完整式。

口令输入会做归一化:大写、去掉分隔符,并把 `O→0`、`I/L→1` 这类易混字符映射回 Crockford 字母表。

## 5. 手机端行为

入口:设置 →「备份与导出」→「局域网导出(扫码)」→ 独立路由页。四个状态:

1. **扫码中**:相机预览 + 自绘取景框(压暗层中央掏方孔 + 四角标;识别成功闪绿一下 + 短震动)+「手电筒」文字按钮 +「手输」入口。解码用**整帧**(框只是引导,不是裁剪)。
2. **已识别目标**:立即释放相机,显示目标地址与口令,选择发送内容。
3. **发送中**:显示目标地址与进度。
4. **成功 / 失败**:成功显示电脑上的落盘路径 + 校验一致;失败显示具体原因 + 重试。

约束:

- **绝不自动发送。** 扫到只是识别目标,必须用户点按钮。
- **屏幕无状态**:脚本每次重启换口令,"记住上次目标"没有意义;不写 SharedPreferences。
- 权限:只新增 `INTERNET` 与 `CAMERA`(运行时申请)。相机被拒 → 直接给手输入口;被永久拒绝 → 跳系统设置。**不申请 `ACCESS_NETWORK_STATE`**:网络问题靠连接失败的分类提示。
- 失败提示要能定位问题:连不上(脚本没跑/防火墙/不同网段)、15 秒无响应、口令不匹配(脚本重启会换口令)、文件过大、应答异常(带状态码)。
- 发送中的协程随页面离开而取消;因为电脑端是原子落盘,取消不会留下半个文件。

## 6. 为什么手写裸 socket,而不是 `HttpURLConnection`

`targetSdk` 37 下,Android 9+ 的**明文策略**会拦截应用 HTTP 栈发起的明文请求,要走 `HttpURLConnection` 就得在 manifest 里加 `usesCleartextTraffic`(全局放开,且没法按子网收窄)。

裸 socket 手写这一个 POST:

- 不触发该策略,manifest 保持干净;
- **绕过系统代理**,保证真的直连局域网;
- 请求与应答两端都在我们手里,HTTP/1.1 只用最朴素的一问一答(~40 行,可审计)。

代价是自己写状态行与头解析;若实测发现平台仍拦截,退回 `HttpURLConnection` + `usesCleartextTraffic`,并在此文档写明原因。

## 7. 安全边界(必读)

- **明文 HTTP,没有 TLS。** 同一局域网里能嗅探的人就能看到口令与文件内容。
- **"口令"不能认证主机。** 手机把口令发给"你输入的地址";如果那是伪造的地址,伪造者拿到口令和数据。口令的真正作用是:① 接收脚本只接受自己人的推送;② 发送到错误地址时不会静默成功。**保密性由网络本身提供。**
- **二维码 = 谁贴谁收。** 别扫来源不明的二维码;应用侧的对策是显示目标地址 + 绝不自动发送。
- **最严谨的用法**:手机开热点、电脑连手机热点。链路上只有你两台设备,没有第三方可嗅探,地址也稳定。
- **常驻即窗口无限长**:脚本忘了 `Ctrl-C` 就一直开着。要收窄窗口就 `--idle-timeout`。
- 接收端不做目录穿越(`basename`)、不覆盖同名文件、超限拒收、口令失败限速(六位 Crockford base32 ≈ 30 bit,叠上每次失败 0.5 s 的延迟,暴力枚举不可行)。

## 8. 明确不做

反向导入(电脑 → 手机)、mDNS/DNS-SD 发现、UDP 广播探测、HTTPS/自签证书、公网中转、IPv6、多台电脑同时接收。

## 9. 审计指引

| 权限 | 用途 | 代码位置 |
|---|---|---|
| `INTERNET` | 仅用于你手动开启的局域网导出:直连你输入的电脑地址 | `data/lan/LanExportClient.kt` |
| `CAMERA` | 仅用于扫那个二维码(运行时申请,可拒绝) | `ui/lanexport/` |
| `POST_NOTIFICATIONS` / `SCHEDULE_EXACT_ALARM` / `RECEIVE_BOOT_COMPLETED` / `VIBRATE` | 提醒相关(与网络无关) | `alarm/` |

应用**不含**任何主动外联代码:没有 HTTP 客户端库、没有统计/崩溃上报、没有服务器地址。接收脚本在电脑上,不在这个 APK 里。

不用手机、只用手工命令验证接收端:

```bash
curl -X POST http://192.168.2.110:47821/upload \
  -H "X-Kusuri-Code: K4F9M2" \
  -H "X-Kusuri-Kind: json" \
  -H "X-Kusuri-Filename: kusuri-backup.json" \
  --data-binary @kusuri-backup.json
```
